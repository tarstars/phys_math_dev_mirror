# Вычисление строки треугольника Паскаля за линейное время: Часть 1

Позвольте мне объяснить, почему, после того как я рассказал вам о [количестве путей, по которым может двигаться робот](<https://t.me/phys_math_dev/302>), я вдруг почувствовал сентиментальность и написал о [Евгении Панкратьеве](<https://t.me/phys_math_dev/304>).

В [задаче 62](<https://github.com/tarstars/leetcode/blob/main/rust/0062/ps.md>) робот телепортируется в верхний левый угол, поэтому существует только один возможный путь, чтобы добраться до него.

![Post image](<https://pub-df8eda899f364205ba20a32dc3740d46.r2.dev/telegram/phys_math_dev/015370a477e8343057852c0b63f5bfbbd25b6f373cae86216758bfe89fad1090.jpg>)

Когда робот может двигаться только горизонтально, существует только один способ посетить каждую ячейку в верхней строке. Аналогично, существует только один способ добраться до каждой ячейки в левом столбце.

![Post image](<https://pub-df8eda899f364205ba20a32dc3740d46.r2.dev/telegram/phys_math_dev/0f12c04edf5177c1ceb95a8e42cdd83d7489c1077f83a44f6b0a1a04bdb0587a.jpg>)

Самое интересное происходит, когда робот может добраться до ячейки либо, двигаясь вправо, либо вниз. В этом случае, количество способов добраться до ячейки равно сумме количества способов добраться до ячеек, расположенных выше и слева.

![Post image](<https://pub-df8eda899f364205ba20a32dc3740d46.r2.dev/telegram/phys_math_dev/1a904a1f84fc2722a8f4804a131100c1c1d771f11e5e566085b11773cd5a2b44.jpg>)

Как вы видите, решение с использованием динамического программирования выглядит следующим образом (и вы должны написать его именно так на собеседовании).

```rust
fn path_number(h: usize, w: usize) -> i32 {
    assert!(h > 0 && w > 0);

    let mut c = vec![vec![0; w]; h];

    c[0][0] = 1; // the robot starts at the top-left cell

    for q in 1..w {
        c[0][q] = 1;
    }

    for p in 1..h {
        c[p][0] = 1;
    }

    for p in 1..h {
        for q in 1..w {
            c[p][q] = c[p - 1][q] + c[p][q - 1];
        }
    }

    c[h - 1][w - 1]
}
```
