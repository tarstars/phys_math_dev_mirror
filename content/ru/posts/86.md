MapReduce в The Farmer был заменен

Обсуждение кода. Часть I.

27 лет назад родился Google. Одной из ключевых идей был PageRank – показатель «достоверности» веб-страницы. (бумага) Чтобы вычислить это быстро, вам нужна большая вычислительная мощность. Один из вариантов — построить специализированный суперкомпьютер, но Google как компания отвергла этот путь. Вместо этого они решили использовать большие массивы аппаратного обеспечения стандартного класса, подключенного к сети. Необходимо тщательно организовывать программы, работающие на такой платформе, а в те времена написание распределенных вычислений было почти колдовством.

В 2004 году началась новая эра распределенных вычислений — эра платформ MapReduce (см. статью Дина и Гемавата). Идея проста: разделите данные на части, запустите одну и ту же функцию «карты» параллельно на многих машинах, затем объедините («сократите») частичные результаты в один конечный результат.

Этот пост посвящен адаптации этого подхода к задаче по сбору подсолнухов в игре «Фермер был заменен».

Внутриигровое задание состоит из трех этапов: подготовить почву, посадить подсолнухи, собрать урожай. Мы хотим использовать бонус 5×, поэтому пытаемся собирать подсолнухи в порядке меры(): от большего к меньшему. Я говорю о поздней части игры, когда у меня есть поле 32×32 и 32 дрона, поэтому я могу назначить по одному дрону на каждый столбец или строку.

Мне нужна была крошечная «структура», позволяющая назначать задачи дронам и запускать их параллельно. Поскольку мы проводим измерения, нам также необходимо собирать данные с разных дронов и объединять их. Ядром этого фреймворка является функцияdrone_map_reduce из скрипта.

Функцияdrone_map_reduce принимает три параметра:

⌖ объекты – вещи для обработки
⌖ f_map – функция, обрабатывающая пакет объектов
⌖ f_red — функция-редьюсер, которая объединяет результаты каждого пакета в один большой результат.

API дронов, на который мы полагаемся:

⌖ spawn_drone(f) – запускает функцию f, запускающую дрон, и возвращает идентификатор дрона.
⌖ дрон «исчезает», когда заканчивается f
⌖ wait_for(drone_id) – ждет завершения работы дрона и возвращает результат

Сначала создаем слоты для дронов и распределяем между ними задания:

def drone_map_reduce(objects, f_map, f_red):
    drone_jobs = []

    for _ in range(max_drones()):
        drone_jobs.append([])

    ind = 0
    for q in objects:
        drone_jobs[ind % len(drone_jobs)].append(q)
        ind += 1

Теперь каждый элемент вdrone_jobs — это пакет работ для одного дрона (или для основного потока).

Затем запускаем дронов и также обрабатываем некоторые пакеты в основном потоке:

    results = []
    drones = []

    while drone_jobs:
        while drone_jobs and num_drones() < max_drones():
            current = drone_jobs.pop()
            drones.append(spawn_drone(f_map(current)))
        if drone_jobs:
            current = drone_jobs.pop()
            results.append(f_map(current)())

После этого собираем все результаты с дронов:

    for current_drone in drones:
        results.append(wait_for(current_drone))

И, наконец, объединяем все в один результат с помощью f_red:

    for r in results:
        if reduced is None:
            reduced = r
        else:
            reduced = f_red(reduced, r)

Несколько важных деталей:

⌖ Чтобы создать допустимое задание дрона, f_map ожидает список элементов того же типа, которые вы храните в объектах.
⌖ Мы создаем пакеты размером до max_drones(), поэтому во внутреннем цикле мы просто создаем дронов до тех пор, пока num_drones() не достигнет max_drones().
⌖ Код по-прежнему работает, когда количество задач меньше количества дронов (например, с помощью set_world_size(3)); некоторые партии просто оказываются пустыми.
⌖ Если ваша функция дрона ничего не возвращает (Нет) и вас не волнуют результаты, вы можете передать фиктивный редуктор, например no_reduce, который игнорирует свои аргументы. Или даже просто значение None для функции редуктора, потому что она никогда не будет вызываться.
