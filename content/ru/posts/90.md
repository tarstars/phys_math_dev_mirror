MapReduce в The Farmer был заменен

Обсуждение кода. Часть II.

В предыдущем посте мы обсуждали код, который использует подход уменьшения карты для выращивания подсолнечника. Мы рассмотрели функциюdrone_map_reduce(objects, f_map, f_red) построчно и поняли, что:
👉🏻objects — массив описаний задач
👉🏻 f_map — фабричная функция, создающая задачу по ее описанию.
👉🏻 f_red — функция редуктора, при необходимости объединяет результаты в один большой результат

Сегодня мы обсудим, как эта структура применяется для решения трех задач по подсолнечнику: обработать все поле, посадить подсолнухи, собрать урожай подсолнухов с бонусом х5.

До поля

def till_field():
 columns = []

 for x in range(get_world_size()):
  columns.append(x)

 def till_column(columns):
  def g():
   for q in columns:
    for p in range(get_world_size()):
     nav(q, p)
     till_soil()
  return g

drone_map_reduce(столбцы,til_column,no_reduce)

Давайте проверим этот код. Сначала мы подготавливаем список столбцов для обработки. Затем мы подготавливаем фабричную функциюtil_column, которая принимает список столбцов для обработки и возвращает... Внимание!!! — функция для обработки всех этих столбцов. Он использует вспомогательные функции: nav для навигации иtil_soil для обработки пастбищ в Soil (он не обрабатывает их обратно). Мы используем довольно интересный трюк — вложенную функцию g внутрь функцииtil_column. Он фиксирует переменную столбцов и, следовательно, самосознателен и может работать без параметров. В «нормальном» программировании это похоже на «частичную» функцию, которая связывает параметры со значениями. Эта функция вызывается внутри функции spawn_drone и определяет действия дрона и его время жизни.

Посадить подсолнухи

def plant_sunflowers():
  drone_jobs = []

  for q in range(get_world_size()):
    drone_jobs.append(q)

  def drone_job(columns):
    def g():
      heights = dict()
      for q in columns:
        for p in range(get_world_size()):
          nav(q, p)
          plant(Entities.Sunflower)
          heights[(q, p)] = measure()
      return heights
    return g

  def reduce_hights(h1, h2):
    for k in h2:
      h1[k] = h2[k]
    return h1

returndrone_map_reduce(drone_jobs,drone_job,reduce_hights)

Первая часть вполне знакома — формирование списка столбцов для обработки. Функцияdrone_job снова представляет собой фабрику функций. Опять же, эти функции очень похожи на предыдущие функцииtil_column. Но теперь у нас есть интересная деталь. У каждого подсолнуха есть свое количество лепестков, и по этим лепесткам мы должны определить, какой подсолнух собирать первым. Итак, после посадки подсолнуха мы вызываем функцию Measure() и помещаем ее результат в словарь:
высоты[(q, p)] = мера()
Ключами этого словаря являются кортежи координат, а значениями — номера лепестков.

И последняя, ​​но не менее важная деталь: функция уменьшения_высот. Он принимает в качестве параметров два словаря, обновляет первый значениями из второго и возвращает этот первый словарь. Тут логика всего дела немного сложная и я это намеренно сделал. В моей первой версии код был более понятным: я каждый раз создавал новый словарь и заполнял его содержимым двух параметров. Но в данном случае дрон неожиданно остановился на заметно долгое время. Оказалось, что цена чистого кода — квадратичная сложность алгоритма. Поэтому я изменил его, и теперь вы видите более беспорядочный, но более быстрый код.

Я не уверен, что один пост может содержать столько кода, поэтому давайте использовать ссылки на github. Начиная с этой строки, я конвертирую словарь из формата (x,y) -> h в h -> [(x1, y1), (x2, y2), ...]. Для каждой высоты подсолнуха теперь у нас есть список ячеек с подсолнухами данной высоты в этих ячейках.

Наконец, мы используем наш подход map_reduce, чтобы собрать все подсолнухи в правильном порядке. «gather_all» — фабричная функция для этой задачи.
