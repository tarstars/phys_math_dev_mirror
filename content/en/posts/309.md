# Shades of inefficiency

The worst thing you can do when someone asks you to calculate binomial coefficients or Fibonacci numbers is to write a function that implements the definition of these objects from a schoolbook verbatim.

 $f(n) = f(n - 1) + f(n - 2),\quad f(1) = 1, f(2) = 1$

$C_n^k = C_{n - 1}^{k - 1} + C_{n - 1}^k,\quad C_n^0 = C_n^n = 1$

The straightforward approach looks like this:

```python
def c(n, k):
    if n == k or k == 0:
        return 1
    return c(n - 1, k - 1) + c(n - 1, k)

def f(n):
    if n < 3:
        return 1
    return f(n - 1) + f(n - 2)

```

Due to a beautiful symmetry, the recurrence for the number of function calls is almost exactly the same as the one for the function itself. It means that the running time explodes exponentially. The simple remedy is to use cache or lru\_cache from functools module or a hash table in other languages:

```python
from functools import cache

@cache
def f(n):
    if n < 3:
        return 1
    return f(n - 1) + f(n - 2)
```

```python
from functools import lru_cache

@lru_cache(maxsize=128)
def f(n):
    ...
```

So, the worst solution for $C_n^k$ is $T=O(2^n)$. Let's think that k is around $n/2$. The next improvement one can make is to consider $C_n^k$ as element of a table (Pascal's triangle) and build it literally. This gives $T=O(n^2)$ and $M=O(n^2)$. That's better. Next trick - use two rows instead of the full table, reduces memory consumption $M=O(n^2)$ \rightarrow $M=O(n)$. Factorial gym gives us, probably, the best solution $$T=O(n)$, $M=O(1)$.$

I like tricks like [the one](<https://t.me/phys_math_dev/308>) from the previous post. I don't like mundane things like watching out for catches when they ask you to calculate $C_{200}^{197}$. In the middle of this row arithmetic explodes with almost $2^{200}$, when it's totally feasible to compute$C_{200}^{197} = C_{200}^3 = \frac {200 \cdot 199 \cdot 198} 6$.

OK, we know $T=O(n), M=O(1)$ solution for $C_n^k$. What about fibonacci? Next time.
