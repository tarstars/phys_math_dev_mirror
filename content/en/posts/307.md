# Calculating a row of Pascal's triangle in linear time: Part 2

![Post image](<https://pub-df8eda899f364205ba20a32dc3740d46.r2.dev/telegram/phys_math_dev/d1d8b04a8b6cde3cea41de0dec78007ef9fa9a326e061aed7ba6d1506ca93f4f.jpg>)

It's the famous Pascal's triangle. Ones on the roof. Each element below is equal to the sum of its two upstairs neighbors. My first attempt to write a program that calculated Pascal's triangle, thirty years ago, failed because I actually tried to reproduce this equilateral picture from books.



![Post image](<https://pub-df8eda899f364205ba20a32dc3740d46.r2.dev/telegram/phys_math_dev/06d0790ce6997b722759b9360e0f909d2e7d661d1560013071e78eb46fd9700e.jpg>)

When I draw it like this, it becomes way more programming-friendly. We pay for it with left-right symmetry, but in return we get a clear and uniform recurrence relation:

$C_n^k = C_{n-1}^k + C_{n-1}^{k-1}$

The neighbors now live directly upstairs and upstairs to the left.

The next thing with which I'm not quite comfortable even now is skew transform:$f(x, y) = C_{x + y}^x$. It's because we are talking about the robot who wants to make x steps to the right (x ones) and y steps down (y zeros). There are $C_{x + y}^x$ ways to create the string which consists of x ones and y zeros. Or $C_{x + y}^y$ - because of the symmetry. This way you can see exactly the table from the previous post.



![Post image](<https://pub-df8eda899f364205ba20a32dc3740d46.r2.dev/telegram/phys_math_dev/372a9382d151b7b6e787204bd3e0f5d2d61655e9686fe5d929a065c438e4c464.jpg>)



So far, we've seen two faces of binomial coefficients: recurrence and combinatorics. Now we can use them to count paths for the robot. Be careful. In the problem statement $m$ and $n$ are height and width of the rectangular grid. The numbers of steps in each direction is one smaller: $x = m - 1$ to the right and $y=n-1$ down. One last step remains: calculate $C_{x + y}^y$ efficiently. Let's do it next time.
