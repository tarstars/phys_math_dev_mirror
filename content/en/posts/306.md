# Calculating a row of Pascal's triangle in linear time: Part 1

Let me explain why, after telling you about [the number of robot paths](<https://t.me/phys_math_dev/302>), I suddenly got sentimental and wrote about [Evgeniy Pankrat'ev](<https://t.me/phys_math_dev/304>).

In [Problem 62](<https://github.com/tarstars/leetcode/blob/main/rust/0062/ps.md>), the robot teleports to the top-left cell, so there is only one possible path to reach it.

![Post image](<https://pub-df8eda899f364205ba20a32dc3740d46.r2.dev/telegram/phys_math_dev/015370a477e8343057852c0b63f5bfbbd25b6f373cae86216758bfe89fad1090.jpg>)

When the robot can move only horizontally, there is only one way to visit every cell in the top row. Similarly, there is only one way to reach each cell in the leftmost column.



![Post image](<https://pub-df8eda899f364205ba20a32dc3740d46.r2.dev/telegram/phys_math_dev/0f12c04edf5177c1ceb95a8e42cdd83d7489c1077f83a44f6b0a1a04bdb0587a.jpg>)

The most interesting thing happens when the robot can reach a cell either by moving right or down. In that case, the number of ways to reach the cell is the sum of the numbers of ways to reach the cells above and to the left.

![Post image](<https://pub-df8eda899f364205ba20a32dc3740d46.r2.dev/telegram/phys_math_dev/1a904a1f84fc2722a8f4804a131100c1c1d771f11e5e566085b11773cd5a2b44.jpg>)

You can see that dynamic programming solution looks like (and you suppose to write it like this on the interview)

```rust
fn path_number(h: usize, w: usize) -> i32 {
    assert!(h > 0 && w > 0);

    let mut c = vec![vec![0; w]; h];

    c[0][0] = 1; // the robot starts at the top-left cell

    for q in 1..w {
        c[0][q] = 1;
    }

    for p in 1..h {
        c[p][0] = 1;
    }

    for p in 1..h {
        for q in 1..w {
            c[p][q] = c[p - 1][q] + c[p][q - 1];
        }
    }

    c[h - 1][w - 1]
}
```
