# The First time Rust really impressed me

![Post image](<https://pub-df8eda899f364205ba20a32dc3740d46.r2.dev/telegram/phys_math_dev/ff89d9951c47088af40126a7fa282de650ec2918b72f904a553b639bb67486cd.jpg>)

c style


![Post image](<https://pub-df8eda899f364205ba20a32dc3740d46.r2.dev/telegram/phys_math_dev/543c704e9b5a4f644925df71cdbf20fb1de300266df411ff4d62b36293ef9cfe.jpg>)

Rust style

You know how this chain goes. I want to understand how to write multi-agent controllers for games like troll\_farm. Python is too slow, so I chose Rust. I don't know Rust, so I'm [learning](<https://github.com/tarstars/leetcode/tree/main/rust>) it by solving leetcode. For the first time, I bumped into something which made me go: WOW.


I'm not impressed by Rust's memory management. Instead of paying attention to pairs of new/delete or malloc/free calls, you have to learn tons of "borrowing" rules and fight the compiler every step of the way. It turned linked-list problems into a hellish nightmare. I hope that it was a useful nightmare, but who knows.


And finally I found IT. Leetcode 31. "Next permutation". I have known the problem and the algorithm since I bought A. Shen's book in 1998. Nice juggling with indices. Or with pointers, if you want. You have to carefully:

- find the rightmost number smaller than its right neighbor. It's a pivot element. No =\> end of algorithm
- swap the pivot with the rightmost greater than it
- reverse the suffix to the right of pivot element


It is exactly what is written on the top picture. But check the bottom one. It's beautiful. You split your sequence into windows of length two, select one which satisfies the predicate. Then - rightmost greater then pivot. Then - swap and reverse. Your algorithm is written in almost like plain English. I don't know yet whether it gives any advantage in programming in general. Nevertheless, in this case, it is beautiful.
